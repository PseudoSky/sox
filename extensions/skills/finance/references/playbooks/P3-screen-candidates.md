# P3 screen-candidates

Stage: screen. Reads: `market-data`, posture from P2. Emits: a candidate list (symbol, screen, score, date) and optionally a plan per candidate.

Run only the screens the user asked for. The VCP screen runs keyless: `market screen --symbols A,B,C`, and its output file feeds P5. For a broad universe, `market universe [--sector S] [--limit N]` lists S&P 500 constituents from a public CSV (cached a week; tickers in Yahoo form), and `market screen --index sp500 [--sector S] [--limit N]` screens them directly; a full index takes minutes and every symbol needs a daily-bars request. The reply's `screen` key is the output file path (feed it to `recommend --screen` and `breakout plan --screen`); `results` is a count of the entries in it. The file holds the best-scoring `--top` (default 20) of the symbols that passed the trend filter; the reply's `funnel` and `truncated` fields say how many passed in all, and `--max-candidates` (default 100) caps how many pre-filtered symbols are analysed in full. The result reports `results` (symbols that passed the trend filter) and `valid_vcp` (the only ones that can become candidates); a weak or no-VCP result is monitor-only. Sector and market cap read Unknown and 0 because fundamentals are not provided. Read the posture from `market posture` (P2) first. Relative-strength percentiles are ranked within the symbols analysed, so the same symbol's score moves a little between a 100-symbol and a 500-symbol run; compare scores only within one run. A screen that needs a key with no `market-data` binding is reported as unavailable, not skipped silently. `stock-recap` moved here from research.
