# Changelog

## Unreleased

- **Correction of apply testing and the foundation targets (39a21823 T48, 595965cc T49).** The literal `gates: own` no longer replaces the gate list: a declaration spelling it supplies the rows as `gateList` (`gatesOf` in `lib.mjs` is the one reader; `validateDeclaration` accepts `routing`, `ownership`, `gateList` and rejects `gates: "own"` without a list). Filing is ordered after every write that needs no uid and before the ledger write, so a failed write cannot orphan filed items, and a ledger write that fails after filing throws an error naming every `gate=uid` it could not record. The `testing-mechanisms` and `foundations-filed` ledger blocks are no longer written with `force`: a hand edit is reported as drift (exit 3), nothing is filed while a ledger or target block is drifted (`wouldFile` and a warning say so), and `--force` replaces. `apply testing --check` on a repository the standard was never applied to exits `5` (`EXIT.NOT_APPLIED`; result `missing` lists the absent blocks and skeleton) instead of 0; drift still takes precedence. The command table is keyed `<gateSet>/<id>`: a row may name its `gateSet`, and a bare-id row binds only while no other standard declares that id (`sharedGateIds`, `isCommanded`). `mechanismFor` no longer names the `testing` standard: each standard's `binding` document and `<id>-mechanisms` ledger are read alike (`mechanismFor` takes `bound` and `shared` instead of `testingBound`; `boundGates` takes the standard id). A pre-existing Capabilities table in `AGENTS.md` is left untouched outside the markers; the `test-routing` row stays in its own table inside the testing block and a warning says so. Template expansion uses replacer functions, so `$&` and `$1` in a repository name or policy path land verbatim. The dead `renderBlock` re-export is removed. Version is left to the Changesets release flow.
- **Closeness-0 bindings are flagged `bound-no-coverage` (595965cc T47 rank0).** Resolution is unchanged. `composeRouting` now returns `boundNoCoverage` (`<standard>/<role>` for every role whose holder covers none of its obligations), adds a `bound-no-coverage:` warning per such role, and shows `none (bound-no-coverage)` in the role-holders table. `applyFoundation` (and so `review routing`) reports `boundNoCoverage` and a `level` of `full` or `lowered`; unbound and closeness-0 roles both lower it. Exit codes are unchanged (a thin roster lowers the reported level instead of failing). Version is left to the Changesets release flow.
- **`resolveRole` follows the closest-available-agent rule (595965cc T47 AC1, MAP 1E.4).** An agent is eligible when it has the role's tools and breaks no independence constraint; obligation coverage no longer gates eligibility, so a zero-coverage agent with the tools is eligible at closeness 0 and is chosen only when no covered agent is. Ranking is closeness, then fewest other roles already held in the change, then `roles.md` hints, then name. A new optional third argument `{ session, held }` applies `distinct-from` inside the function (the authoring session is excluded from a role whose `distinct-from` names a role it holds; a fresh dispatch of the same agent stays eligible) and supplies the held-role counts. The result gains `held`. Calls without the argument keep the static routing-table behavior. Descriptions are never scored. Version is left to the Changesets release flow.

## 0.1.0

- Initial release (item 9024e9ac, T14). Registry (routing and gates foundations, testing standard, five planned standards), standard contract and `roles-covered` schema, the `testing` standard (13 roles with obligation ids, five role cards, seven Test-author playbook cards, run/apply/review/retention-audit/flake-triage playbooks, five record formats, `apply` templates, conformance specification), foundation playbooks, and the scripts `ws.mjs`, `review-all.mjs`, `review-routing.mjs`, `conformance.mjs`. Recorded reuse decision for the gate runner and managed-block writer. `review-routing.mjs` also reports `roles.md` hints that match no installed agent and names a misplaced `agent["roles-covered"]` list.
