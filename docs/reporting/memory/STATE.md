## Known-unverified — do not treat as done

- **BL-409's mitigation covers half the problem.** Pathspec commits stop you sweeping another
  agent's *staged* files; they do nothing about their *uncommitted edits to the same file*, because
  the working tree is shared. For hot files (`BACKLOG.md`, `PLAN.md`, this file) it buys nothing.
  The structural fix is per-agent worktree isolation, which is now the default for dispatch.

### ⚠️ Worktree dispatch has a gap that has already cost verification

Worktrees created by `isolation: "worktree"` inherit **neither `node_modules` nor git hooks**. Two
agents (PKT-31, PKT-53) could not run `nx test` at all and committed with `--no-verify`. Before
dispatching into a worktree, either run `pnpm install` and `node tools/install-git-hooks.mjs` in it,
or accept that the packet's acceptance test will not run — and say so in the report rather than
letting `--no-verify` pass as green.

## Traps that cost real time (don't rediscover these)

- **`grep` is a shell function** and silently returns nothing on a file with a raw NUL byte. Use
  `/usr/bin/grep` when proving something is *absent*. (BL-371.)
- **A stale `-tshm`** makes the store unopenable with an error naming the *wrong* file
  (`short read on WAL frame` while the WAL is 0 bytes). The adapter now handles this at open —
  renaming, never deleting, and only when the WAL is empty. (BL-373.)
- **A sentinel token must be a WHOLE word.** The FTS probe capped tokens at 20 letters, so any row
  containing e.g. `sharedFastembedProcess` reported unindexed on a healthy index — 7.3% of live
  rows. Never truncate a term you are about to search for. (BL-374.)
- **Turso experimental flags are an ARRAY, not an object** — `experimental: ['index_method', 'multiprocess_wal']`.
  `index_method` is required on any connection that will run `fts_match`.
- **A read-only Turso connection cannot run `fts_match`** (`Resource is read-only`) even though
  plain reads work. This is BL-391 and it is why federated recall's BM25 arm is dead.
- **`PRAGMA integrity_check` has a permanent false positive** on any Turso store with an FTS index;
  the probe now filters exactly one known instance. Do not "fix" the store because of it. (BL-360.)
- **Turso PANICS and aborts the process** when opening a store whose FTS index row has no backing
  directory table — so a damage fixture must produce empty-but-present, never absent. (BL-361.)
- **`nx build` deletes the artifact BEFORE knowing the rebuild succeeds** (BL-235), and `--dry-run`
  is silently ignored on a run-target. A diagnostic build is a destructive operation; it has taken
  this server down twice.
- **`registry:sync-index` rebuilds transitively.** Running it after touching an unrelated package
  re-bundled `memory-server` and armed a production deploy nobody chose. (BL-390, now guarded by a
  dirty-tree refusal.)
- **`soxe service enable` rebuilds unit env from YOUR SHELL** and silently drops anything absent. It
  dropped both emergency brakes while reporting success. Diff the plist afterwards. (BL-375.)
- **`ProcessType` must not be "improved" to `Adaptive`** — Adaptive promotes out of Background on
  XPC activity, which sox services never generate. It would look like a fix and change nothing.
  (BL-331.)
- **`duration_ms` is wall-clock** and accrues during system sleep — every p90/p99/max from telemetry
  is inflated. (BL-369.)
- **BL ids collide.** Allocate with `tools/allocate-bl-id.mjs`, never by eye — and delete the
  `RESERVED` placeholder it writes before committing, or the marker check fails on a duplicate id.
- **Never enqueue onto a WriteQueue from inside a task already running on that same queue** — this
  deadlocked `memory_write` on any content over 2000 chars. (BL-154.) ⚠️ **This is a re-entrancy
  rule only.** It is *not* a mandate to serialise Turso writes; do not flip the Turso adapter's
  `needsWriteSerialization` / `concurrentTransactions`. Three agents have made that mistake.
