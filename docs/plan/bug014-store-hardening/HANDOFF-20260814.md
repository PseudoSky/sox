## D. New defects found while doing the repair

1. **`create-item` silently discards `citations`** and reports success. 11/11 items filed with
   31 citations landed with zero; all recovered via separate `add-citation` calls. The repo's own
   rule is "no citation, no claim" — the tool produces exactly the unfileable shape it forbids.
   Agents verify with `get-item` but usually assert existence, not citation survival, so the loss
   is invisible to the prescribed verification step.
2. **A native turso panic leaks the lease AND `.openmark`.** Confirmed twice (pid 12910 dead, both
   files present). A Rust panic cannot be caught by a JS `finally`, so unwind-path cleanup
   structurally cannot run. Orphaned leases make the store look permanently BUSY, which motivates
   the destructive sweep — and that sweep misreads EPERM as death. Leak-then-sweep can clear a
   **live** peer's lease.
3. **Classic SQLite cannot PARSE a turso-created schema.** `PRAGMA integrity_check` fails at schema
   load: `malformed database schema (__turso_internal_fts_dir_idx_fts_node_key) - near "USING"`.
   It worked during forensics only because the DAMAGED file's schema had degraded enough to parse.
   The check is available exactly when the store is broken and absent when it is healthy — the
   worst possible availability pattern. It also undercuts any classic-engine path justified as
   "needed for diagnostics": it cannot do that job.
4. **CLI advertises camelCase keys it rejects.** Validation examples print `humanId`; the parser
   accepts only `--human-id`. Three independent hits this session (add-citation 31/31,
   link-related 17/17, get-item). The get-item case is the dangerous one — **it produced a false
   "all items are missing" conclusion during triage**, because a bad-flag error and a genuinely
   absent item are indistinguishable to a caller grepping for a humanId.
5. **`store.integrity.sidecar_stale` is emitted twice per command**, on every invocation, for a
   condition explicitly documented as non-actionable. Trains operators to filter integrity events.
